# digest（研究消化）

把书、源码、长文档消化成"一个月后还能用它回忆起全部要点"的学习笔记，并在合适的时机把可复用的部分固化成资产。

## 流程

### 1. 先定目标和产出形态

开始前确认（或判断）两件事：
- **学什么、为什么学**：应付面试、指导日常实践、还是纯兴趣——决定详略
- **预期产出**：默认是学习笔记；用户明确说"想做成 skill/cheatsheet"才往资产方向走

### 2. 通读源材料

- **优先一手来源**：原版书 > 翻译版，官方文档 > 二手博客。只有二手来源时说明并提防错漏（机翻腔、过时信息）
- 书：先读目录建立全局地图，再逐章读，注意作者自己的总结章节（通常是全书最浓缩的部分）
- 源码仓库：README → 目录结构 → 核心模块入口 → 关键测试（测试是最诚实的文档）
- 材料太长时采样+跳读，但要在笔记里标注哪些部分是跳读的

### 3. 提炼核心框架

合上书先回答：**这东西的一屏骨架是什么？**（一本书通常能压成 3-5 个核心论点 + 一张结构图）。压不出来就是还没消化，回去再读。

### 4. 产出笔记

结构（按此组织，详略随材料调整）：
1. **核心心智模型**：一屏内的骨架
2. **关键论点展开**：每个论点 = 主张 + 论证逻辑 + 一个例子
3. **可操作清单**：能从书页落到日常动作的部分（检查清单、判断问题、口诀）
4. **我的评注**：哪里同意、哪里存疑、和自己经验的冲突——**明确和作者观点分开**，不混写

红线：
- **提炼重写，不整段搬运原文**——搬运既没消化也有版权问题；能用自己的话讲出来才算学会
- 笔记写给"一个月后的自己"，不写给作者交差

### 5. 判断：知识还是习惯？（关键一步）

消化完后问一个问题：**"这东西会在某个具体场景下改变我的行为吗？"**

- 不会 → 就是知识，留在笔记里，结束
- 会 → 列出候选场景，**但不急着做 skill**。等同一个场景真实出现第二次、且笔记里的内容确实被用上了，再固化成 skill
- 反例教训：直接把一本书做成"知识型 skill"——触发模糊、没有动作，最后不伦不类。skill 按场景组织，不按知识组织

### 6. 自审

- 只看笔记能回忆起源材料的主要论点吗？
- 可操作清单里的每条，能说出它在什么场景用吗？
- 评注和作者观点分得清吗？

## 笔记存放

默认放在用户指定的学习目录（如 `源码学习/<主题>/`），文件名用主题名；不放 skills 目录，除非走完第 5 步的"第二次出现"验证。
